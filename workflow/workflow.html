OneDoor — Student Support Triage Workflow

As built: React front end · Node API proxy · Gemini 3.5 Flash Lite · browser localStorage

1. STUDENT INTAKE

Student types a freeform message and/or picks quick category chips (hints).

WellbeingAcademicMoneyHousingGeneral
▼

2. ANALYSIS SCREEN (loading)

App runs detectCrisis(text) in the browser and starts triage.

▼

3. LOCAL SAFETY GATE (always first)

Regex pattern scan in the browser. Decides crisis vs. safe. The AI never makes this decision.

CRISIS PATH

Keyword triage runs locally. No network call — never sent to AI.

→ Crisis screen: immediate 24/7 support contacts.

Safe ↓

4. BROWSER → OUR NODE API  (POST /api/triage)

  • Client timeout 6 s
  • Server: rate limit 30/min/IP, body ≤ 8 KB, text ≤ 2000 chars, hints validated
  • Repeats the crisis check — refuses with 422 if crisis (defence in depth)
  • No API key set → 503
▼

5. GEMINI 3.5 FLASH LITE (server-side only)

  • API key never reaches the browser; store:false; student text never logged
  • JSON schema: category, urgency (Low / Medium / High), recommended service, 2–3 reasons for the student, neutral advisor summary, also-mentioned categories, confidence
  • 5 s timeout, no retry. Schema has no crisis field

FALLBACK: KEYWORD TRIAGE

Runs in the browser when AI is not configured, errors, times out, returns a non-200 or returns invalid JSON.

Student sees no difference.

▼   normalizeResult() validates every field — invalid → fallback

6. RECOMMENDATION

Recommended service, urgency badge, reasons, “also mentioned” tags. The student can change the service.

▼

7. STUDENT CONSENT

Yes → AI summary stored with the request.   No → summary dropped.

▼

8. REQUEST CREATED & CONFIRMED

  • Sequential ID (OD-1042, OD-1043, …) via createRequest()
  • Saved to browser localStorage (prototype — no database)
  • Confirmation screen → “My requests” list
Not built yet: advisor queue / backend delivery · pre-send notice that text goes to an external AI · server-side ticket IDs. If Gemini flags a crisis, it is only logged — routing always follows the local safety gate.
